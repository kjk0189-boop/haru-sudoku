- [난이도와 자동 생성](difficulty.md): 네 단계 수용 기준, 풀이 증거, 반복 방지와 성능

- [네이비·화이트 디자인](visual-design.md): Pretendard·Manrope, 오류 색상, 설치 없는 모바일 웹 미리보기
- [설계 결정](decisions.md): 선택한 방법과 이유, 대안, 제약
- [코드 연결 구조](code-map.md): 모듈의 책임과 의존 관계
- [검증 기록](verification.md): 실행한 검사, 결과, 미검증 사유
- [개발 기록](development-log.md): 날짜별 작업과 남은 일
- [변경 이력](changes.md): 사용자 요청별 동작 변경과 설정 위치
- [배포 안내](deployment.md): 로컬 실행, GitHub Pages 배포

## LLM 기록 규칙
1. 작업 시작 시 목차와 관련 페이지를 읽는다.
2. 확정된 요구사항, 의사결정 이유, 근거 코드 링크를 기록한다. 비공개 사고 과정이나 자격 증명은 기록하지 않는다.
3. 작업 완료 시 실제 검증 명령과 결과, 미검증 항목과 이유를 남긴다.
4. 문서 간 상대 링크를 유지하고, 자동 생성 코드 그래프는 소스 변경 후 재생성한다.
5. 후속 에이전트는 개발 기록의 남은 일과 Git 상태부터 확인한다.
