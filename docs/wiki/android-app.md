## 화면과 플레이
- 홈에서 클래식 이어하기·새 게임·오늘의 도전을 선택한다. 새 게임은 기존 네 단계의 논리 검증을 그대로 따른다.
- 클래식 한 게임과 날짜별 매일 도전은 별도로 보관한다. 매일 도전은 한국 날짜와 버전이 붙은 고정 시드로 생성하는 보통 난이도다. 서버 없이 같은 생성기 버전에서 같은 날짜는 같은 문제가 된다. 미래 날짜는 잠겨 있다.
- 게임에서는 보드·숫자판·도구에 집중한다. 홈으로 이동하면 진행을 저장하고 시간을 멈춘다. 부가 안내는 더보기와 하단 패널을 사용한다.
- 내 기록은 시작·완료·중단, 완료율, 완료한 게임의 최고·평균 시간, 전체 누적 시간·힌트·실수와 최근 10개를 표시한다. 난이도·모드별 필터를 지원한다. 실수는 정답과 다른 숫자를 실제 입력한 횟수이며 게임 종료 제한은 없다.

## 저장과 호환성
- [library.ts](../../src/library.ts): `haru-sudoku:library:v1`에 클래식 한 개, 최근 접근한 매일 도전 30개를 저장한다. 오래된 날짜는 재생성할 수 있지만 보드 진행은 사라진다.
- [player.ts](../../src/player.ts): `haru-sudoku:profile:v1`에 실행 ID별 최대 500개 기록을 저장한다. 완료 기록은 고정하여 새로고침·재진입으로 중복 집계하지 않는다. 날짜별 도전 완료 수는 날짜 중복을 제외한다.
- 기존 단일 게임 저장은 첫 실행에 이전한다. 과거에 수집하지 않은 기록은 복구할 수 없으며 이전 시점부터 기록한다. 앱 시작 시 저장된 게임을 기록과 대조해 복구한다.
- 브라우저와 APK는 별개 저장 공간이다. 웹 기록의 APK 자동 이전·계정 동기화·내보내기는 아직 없다. 앱 삭제·데이터 초기화 시 기록이 사라질 수 있다.

## 무료 도움과 향후 이용 정책
- 힌트와 자동 메모는 현재 모두 무료·무제한이다. 무료 배지를 표시한다. 사용 성공 후에만 횟수가 증가하고 되돌리기는 사용 횟수를 환불하지 않는다.
- [access.ts](../../src/access.ts)의 `DEFAULT_ACCESS_POLICY.mode`는 `free`다. 향후 `metered`에서 기능별 무료 횟수, 재화 비용, 보상형 광고 필요 여부를 판단하도록 준비했다. [policy.ts](../../src/policy.ts)의 난이도별 힌트 제한도 유지한다.
- 실제 재화 지갑·차감·광고 SDK·보상 검증·결제는 구현하지 않았다. 광고 필요 판단은 이용을 허가하지 않으며 보상을 흉내 내지 않는다. 유료 정책을 공개하기 전 실제 보상 흐름과 남은 횟수 UI를 구현·검증해야 한다. 비용 30/50은 비활성 준비값이다.

## Android 구성
- Capacitor 8로 빌드된 웹 자산을 APK에 내장한다. 원격 웹 주소를 열지 않으므로 게임 자산·문제 생성에 인터넷이 필요하지 않다. 외부 폰트 요청도 제거했다.
- 앱 ID `io.github.kjk0189boop.harusudoku`, 이름 하루 스도쿠, Android 7.0/API 24 이상, 세로 화면. 앱 아이콘과 시작 화면을 포함한다.
- Android 뒤로가기는 열린 안내 닫기 → 게임에서 홈 → 다른 탭에서 홈 → 홈에서 앱 최소화 순서다. 백그라운드 이동은 게임을 일시정지한다. 시스템 안전 영역은 Capacitor CSS 속성과 브라우저 env 값을 함께 고려한다.
- [설정](../../capacitor.config.ts), [네이티브 프로젝트](../../android/), [빌드 워크플로](../../.github/workflows/android-apk.yml).

## 개인 테스트 APK 만들기와 설치
1. GitHub Actions에서 **Build Android test APK → Run workflow → main**을 실행한다. 테스트·타입·웹 빌드·그래프 최신성 검사 후 Android 동기화·debug APK 컴파일·서명 및 manifest 검증을 수행한다.
2. 성공한 실행의 **haru-sudoku-debug** artifact ZIP을 내려받아 APK를 꺼낸다. artifact는 30일 보관된다. 공개 스토어 등록이나 등록비는 필요 없다.
3. APK를 휴대폰으로 전송해 연다. Android에서 해당 파일 앱/브라우저의 설치 허용을 요청하면 사용자가 허용하고 설치한다.
4. 비행기 모드 실행, 네 난이도 생성, 홈 이어하기, 매일 도전, 메모·힌트, 기록, 뒤로가기, 화면 껐다 켜기를 확인한다.

개인 테스트용 debug 서명이다. CI 실행마다 서명이 달라질 수 있어 다음 APK 설치 시 기존 앱 삭제가 필요할 수 있으며, 삭제하면 기록도 사라질 수 있다. 지속 업데이트용 서명키 보관·release 빌드·스토어 배포는 별도 작업이다. 서명키나 자격 증명은 Git에 저장하지 않는다.

## 검증 범위와 남은 일
자동 테스트와 브라우저 확인 결과는 [검증 기록](verification.md)에 기록한다. 이 PC에는 Java·Android SDK·연결된 Android 기기가 없어 로컬 네이티브 빌드와 실기기 설치·안전 영역·성능을 확인할 수 없다. GitHub APK 컴파일 성공도 실기기 검증을 대신하지 않는다.
