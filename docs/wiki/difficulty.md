# 네 단계 난이도와 자동 생성

[목차](index.md) · [설계 결정](decisions.md) · [생성 실측](generation-audit.json) · [검증 기록](verification.md)

## 확정 요구사항 / 2026-10-25
사용자가 입문을 제외하고 **쉬움·보통·어려움·전문가** 네 단계를 승인했다. 고정 9문제 순환 대신 새 문제를 생성하고, 아래 조건을 모두 통과해야 제공한다.

1. 정답이 정확히 하나다.
2. 추측 없이 지원하는 논리 기법으로 끝까지 풀린다.
3. 선택한 단계로 평가된다.
4. 풀이 단계·기법·후보 수를 기록하고 재검증할 수 있다.
5. 최근에 플레이한 문제와 정확히 같은 숫자·단서 배치를 반복하지 않는다.

## 평가기 v1
기법 적용 순서는 단일 후보 → 숨은 단일 후보 → 후보 잠금(상자/행/열) → 드러난 후보 쌍 → 행/열 X-Wing이다. 쉬운 기법이 있으면 먼저 사용하며 되짚기나 가정은 사용하지 않는다.

| 단계 | 평가기 기준 |
| --- | --- |
| 쉬움 | 단일·숨은 단일 후보만으로 완주, 부담 점수 100 미만 |
| 보통 | 단일·숨은 단일 후보만으로 완주, 부담 점수 100 이상 |
| 어려움 | 기본 기법만으로는 정체, 후보 잠금 또는 후보 쌍을 사용해 완주 |
| 전문가 | 어려움까지의 기법으로는 정체, X-Wing을 사용해 완주 |

부담 점수 = **최초 빈칸 수 + 숨은 단일 후보 배치 횟수×3 + 즉시 확정 가능한 칸이 1~2개인 단계 수×2**.
기법 기준이 점수보다 우선한다. 어려움의 점수가 보통보다 작을 수 있으며, 이는 다른 종류의 추론이 필요하기 때문이다.

매 단계에는 배치·후보 제거·한국어 설명·즉시 확정 가능한 칸 수·전체 후보 수를 저장한다. 총점, 병목 단계 수, 전체 후보 최대치도 기록한다. 숫자 개수만으로 등급을 정하지 않는다.

이 수치는 하루 스도쿠의 초기 기준으로 보편적 표준이나 사용자 소요 시간 예측값이 아니다. ‘필요한 기법’은 고정 순서 평가기에서 낮은 수준의 기법으로 정체되는지를 의미하며, 가능한 모든 논리 풀이 경로 중 최소 난도를 증명한다는 뜻은 아니다. 실제 플레이 기록으로 경계값을 보정해야 한다.

## 생성과 수용
- [generator.ts](../../src/generator.ts)가 seed 기반 무작위 탐색으로 새 정답판을 만든다. 기존 정답판을 단순 재배열하는 방식이 아니다.
- 무작위 순서로 숫자를 지우고 `countSolutions(..., 2) === 1`일 때만 제거를 유지한다.
- 논리 평가가 완주하고 등급과 정답이 일치하는 문제만 반환한다. 지원 기법으로 풀리지 않는 문제는 전문가로 밀어 넣지 않는다.
- 쉬움은 생성 때 65~94, 보통은 100~114 사이에서 목표 부담 점수를 무작위로 정하고 목표 이상이면서 해당 등급인 문제를 찾는다. 동일 난이도에서 지나치게 단순한 첫 결과만 반복되는 것을 줄이는 생성 정책이며 평가 경계 100은 유지한다.
- 최근 80개의 81자리 단서 지문과 현재 문제를 제외한다. 구조적으로 동형인 모든 스도쿠까지 판별하는 기능은 아니다.
- 초기 실행에만 검증된 [쉬움 시작 문제](../../src/starter.ts)를 사용한다. 새 게임은 매번 생성기를 사용한다.

## UI와 성능
- [Worker](../../src/generator.worker.ts)에서 최대 20초 탐색한다. UI는 생성 안내와 취소 버튼을 표시한다.
- [클라이언트](../../src/generator-client.ts)는 취소 시 Worker를 종료하고, 오류·무응답은 최대 35초에 정리한다. 개별 탐색 연산 중 20초를 조금 넘길 수 있어 35초의 최종 제한을 둔다.
- 목표 등급을 못 찾으면 기존 게임을 보존하고 재시도를 안내한다. 다른 등급의 문제를 대신 제공하지 않는다.
- 현재 구현은 요청 시 생성한다. 다음 문제를 미리 만드는 캐시는 아직 추가하지 않았다.

## 저장과 힌트
- 생성 문제는 원본 단서·정답과 풀이 증거를 게임 기록에 함께 저장한다. ID만 저장해 복원을 못 하는 문제가 생기지 않도록 했다.
- 복원 시 정답·단서·지문·등급을 재검증하고 풀이 증거를 다시 계산한다. 기존 9문제의 저장은 원래 등급으로 이어간다.
- 후보 제거를 거쳐야 하는 힌트도 제거 이유부터 설명한 뒤 한 칸을 채운다. 네 단계 모두 현재는 무제한이며 난이도별 제한 설정은 유지한다.

## 재현과 한계
`node node_modules/tsx/dist/cli.mjs scripts/audit-generation.ts` 또는 `pnpm audit:generation`으로 단계별 seed 1~10을 생성하고 별도로 재평가해 [실측 JSON](generation-audit.json)을 갱신한다.
실측 시간은 해당 데스크톱 환경의 결과다. 실제 모바일 기기 속도, 전체 seed 공간에서의 성공률, 체감 난이도는 별도 검증이 필요하다. 시간 제한 실패 경로는 정상 동작으로 처리한다.
