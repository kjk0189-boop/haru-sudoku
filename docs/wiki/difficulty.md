# 네 단계 난이도와 자동 생성

[목차](index.md) · [설계 결정](decisions.md) · [v2 생성 실측](generation-audit.json) · [v1 기준 실측](generation-audit-v1.json) · [검증 기록](verification.md)

## 공통 요구사항
사용자가 승인한 **쉬움·보통·어려움·전문가** 네 단계를 유지한다. 새 문제는 정답이 하나이며, 가정·추측 없이 지원하는 논리 기법으로 끝까지 풀려야 한다. 정답·요청 단계·최근 중복을 검사하고 풀이 과정을 기록한다.

## 생성 정책 v2 / 2026-10-26
기존 40문제에서 단서 평균은 쉬움 29.9개·보통 27.2개·어려움 27.0개·전문가 27.8개로 겹쳤다. 쉬움도 숨은 단일 후보가 평균 9.1회 필요했고, 어려움에는 제거 한 번만 필요한 문제, 전문가에는 X-Wing 한 번만 필요한 문제가 있었다. 사용자 체감 의견을 반영해 **새로 만드는 문제**의 수용 조건을 강화했다.

| 단계 | 단서 수 | 풀이 조건 | 새 부담 지수 |
| --- | --- | --- | --- |
| 쉬움 | 40~46 | 단일·숨은 단일 후보만 사용. 숨은 단일 후보 최대 5회, 시작 시 즉시 확정 가능한 칸 최소 10개 | 70 이하 |
| 보통 | 32~37 | 단일·숨은 단일 후보만 사용하되 숨은 단일 후보 최소 10회 | 105~145 |
| 어려움 | 27~31 | 기본 기법만으로 정체. 생산적인 후보 제거 최소 3단계, 후보 쌍 최소 1회, X-Wing 미사용 | 170~209 |
| 전문가 | 22~26 | 어려움 기법만으로 정체. X-Wing 최소 1회와 전체 후보 제거 최소 4단계 | 210 이상 |

새 부담 지수 = **기존 기본 점수 + 후보 잠금 단계×12 + 후보 쌍 단계×20 + X-Wing 단계×45**.
기존 기본 점수 = **최초 빈칸 수 + 숨은 단일 후보 배치 횟수×3 + 즉시 확정 가능한 칸이 1~2개인 단계 수×2**.

단서 수만 줄이거나 단계 이름만 바꾸지 않는다. 기존 논리 인증 등급과 위 조건을 **모두** 통과해야 제공한다. 생성 정책은 [difficulty-policy.ts](../../src/difficulty-policy.ts)의 `DIFFICULTY_BANDS`, `acceptsDifficulty`, `difficultyEvidence`에 있다. `GENERATION_VERSION`은 2다.

이 지수는 프로젝트 내부 수용 기준이며 사람의 소요 시간이나 보편적 스도쿠 등급을 뜻하지 않는다. 논리 기법은 고정 순서 평가기 기준으로 필요함을 검증한다. 모든 가능한 풀이 경로의 최소 난도를 증명하지는 않는다. 실제 사용자 체감과 기기 성능은 계속 확인해야 한다.

## 논리 인증 v1을 보존하는 이유
평가기는 단일 후보 → 숨은 단일 후보 → 후보 잠금 → 드러난 후보 쌍 → 행/열 X-Wing 순서로 적용한다. 기존 인증의 기본 점수 100 미만/이상은 쉬움/보통, 후보 잠금·쌍은 어려움, X-Wing은 전문가다. 이 인증 알고리즘은 변경하지 않는다.

기존 인증을 유지하면서 새 문제에 추가 수용 조건을 적용해, 기존 게임이 갑자기 다른 등급으로 바뀌거나 복원에서 삭제되는 것을 방지한다. 풀이 단계에는 배치·제거·설명·즉시 확정 가능한 칸 수·후보 수가 계속 기록된다. 힌트도 같은 타당한 논리 과정을 사용한다.

## 생성·실패·성능
- [generator.ts](../../src/generator.ts)는 seed 기반 무작위 탐색으로 새 정답판을 만들고 유일해를 유지하며 단서를 지운다. 기존 정답판의 단순 재배열이나 고정 템플릿 대체가 아니다.
- 쉬움의 목표 단서 수를 범위 안에서 무작위로 정한다. 다른 단계도 해당 단서 범위 안에서 추가 조건을 검사한다.
- 지원 논리로 풀리지 않게 된 삭제는 해당 숫자를 복구하고 다른 삭제를 시도한다. 무효 경로로 계속 내려가며 탐색 시간을 쓰지 않는다.
- 기본 최대 시도는 10,000회이고 Worker 탐색은 기존 20초 제한을 유지한다. 클라이언트 최종 정리는 35초다. 실패 시 기존 게임을 보존하고 재시도를 안내하며 낮은 등급으로 대체하지 않는다.
- 최근 80개 지문과 현재 문제의 정확한 중복을 제외한다. 동형인 모든 스도쿠까지 판별하지는 않는다.
- 최초 실행용 [시작 문제](../../src/starter.ts)도 v2 쉬움 기준으로 교체했다. 새 게임은 매번 생성한다.

단계별 seed 1~10, 총 40개의 v2 감사 결과는 모두 통과했다. 이 데스크톱의 관측값은 다음과 같다.

| 단계 | 실제 단서 범위(평균) | 실제 부담 지수 | 생성 시간 평균 / 최대 |
| --- | --- | --- | --- |
| 쉬움 | 40~46 (43.2) | 39~45 | 0.003초 / 0.007초 |
| 보통 | 32~33 (32.5) | 105~129 | 0.42초 / 1.05초 |
| 어려움 | 27~29 (27.8) | 173~207 | 1.00초 / 2.45초 |
| 전문가 | 23~26 (25.0) | 210~306 | 3.06초 / 8.11초 |

40개 표본의 데스크톱 수치이며 모든 seed·실제 휴대폰 속도를 보증하지 않는다. 전문가 생성은 더 오래 걸릴 수 있고 제한 시간 실패도 가능하다. `pnpm audit:generation`은 독립 재평가·유일해·v2 조건·저장 복원까지 검증하고 JSON을 갱신한다. JSON의 상한 null은 제한 없음을 뜻한다.

## 저장·매일 도전·기록 호환
- 새 ID는 `gen-v2-<seed>-<81자리 단서>`다. [session.ts](../../src/session.ts)는 정답·유일해·논리 인증과 v2 조건을 다시 검증한다. v2 이름만 붙인 약한 기존 문제는 거절한다.
- 기존 `gen-<seed>-...`와 카탈로그 게임은 기존 인증으로 복원한다. 진행·메모·시간·힌트·원래 난이도를 보존하며 자동 재분류하지 않는다. 기존 게임의 `처음부터 다시 풀기`는 같은 문제를 유지한다. **강화된 문제를 보려면 새 게임을 시작한다.**
- 새 매일 도전 생성은 `haru-sudoku:daily:v2:<한국 날짜>` 시드를 사용한다. 이미 저장한 날짜는 저장된 보드 그대로 이어가고, 저장되지 않은 날짜에 새 보통 기준을 적용한다. 같은 날짜·같은 생성 버전에서는 같은 문제다.
- 기존 최고 기록·완료 횟수는 지우지 않는다. 기존 기록과 v2 기록이 함께 집계되므로 완전히 같은 조건의 세대별 기록 비교는 아니다.
- 힌트·고급 메모의 무료·무제한 기본 정책은 그대로다. 난이도를 높이기 위해 도움 기능을 임의로 제한하지 않는다.
